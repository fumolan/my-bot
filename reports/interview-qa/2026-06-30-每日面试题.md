#### 四、具体技术细节：Spring AI 集成示例

```java
// 1. Spring AI ChatClient 对话
@Service
public class AIChatService {
    
    private final ChatClient chatClient;
    
    public AIChatService(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("你是一个专业的技术助手，回答Java后端相关问题。")
            .build();
    }
    
    public String chat(String message) {
        return chatClient.prompt()
            .user(message)
            .call()
            .content();
    }
}

// 2. 定义 MCP 工具
@Component
public class DatabaseTools {
    
    @Tool(description = "查询用户订单信息，输入用户ID返回最近订单列表")
    public List<Order> queryUserOrders(@P(description = "用户ID") Long userId) {
        // 调用数据库查询
        return orderRepository.findByUserId(userId);
    }
    
    @Tool(description = "获取当前系统时间和日期")
    public String getCurrentTime() {
        return LocalDateTime.now().format(
            DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")
        );
    }
}

// 3. RAG 检索
@Service
public class RagService {
    
    private final VectorStore vectorStore;
    
    public String query(String question) {
        // 向量检索相关文档
        List<Document> docs = vectorStore.similaritySearch(
            SearchRequest.query(question).withTopK(3)
        );
        
        // 构建增强上下文
        String context = docs.stream()
            .map(Document::getContent)
            .collect(Collectors.joining("\n---\n"));
        
        // 生成回答
        return chatClient.prompt()
            .user(u -> u.text("基于以下上下文回答问题：\n{context}\n\n问题：{question}")
                .param("context", context)
                .param("question", question))
            .call()
            .content();
    }
}
```

#### 二、STAR 结构——技术故事的"四节点"框架


#### 三、线上 debug 的完整排查方法论

**面试高频排查场景及完整链路：**

```bash
# 场景 1：CPU 飙升到 100%
排查链路：
  top -Hp <pid>         # 查看哪个线程占用 CPU 最高
  printf "%x\n" <tid>   # 线程 ID 转十六进制
  jstack <pid> | grep -A 30 <tid_hex>  # 查看线程堆栈
  → 定位到具体代码行 → 分析根因 → 修复

# 场景 2：接口超时 / 慢查询
排查链路：
  Arthas trace <class> <method>  # 追踪调用链耗时
  EXPLAIN SELECT ...             # 分析 SQL 执行计划
  → 索引失效 / 数据量大 / 锁等待 → 优化

# 场景 3：内存泄漏 / OOM
排查链路：
  jstat -gcutil <pid> 1000 10    # 查看 GC 情况
  jmap -dump:live,format=b,file=heap.hprof <pid>  # 导出堆
  MAT / JProfiler 分析 → 找到最大对象 → 定位泄漏点

# 场景 4：Agent 调用死循环
排查链路：
  检查 Agent 迭代次数 → 检查工具调用历史
  → 检测重复调用同一工具+同一参数
  → 强制终止 → 降级为逐步确认模式
```
